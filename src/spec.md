# Specification

## Summary
**Goal:** Elicit and document the missing “following features” for the AEGIS codebase, confirm how the repo will be ingested into this build environment, and define a consistent initial UI theme (avoiding blue/purple as primary colors).

**Planned changes:**
- Produce a concrete, numbered feature list for the requested additions, with per-feature acceptance criteria covering: user stories, UI screens/components, required English UI copy, data to store (entities/fields/relationships), API/integration needs, roles/permissions, and non-functional requirements.
- Confirm and document the repo ingestion approach by requesting either a zip/upload of the repository contents or a specific list of files to replicate; identify any licensing/attribution needs.
- Define a coherent visual theme (palette, typography, spacing, component styling) and apply it consistently across the initial UI for the imported baseline and any implemented screens, using Tailwind-friendly styling and non-blue/non-purple primary colors.

**User-visible outcome:** A clear, implementation-ready feature specification and repo ingestion plan, plus an initial consistent UI theme direction for AEGIS screens with English user-facing text.
